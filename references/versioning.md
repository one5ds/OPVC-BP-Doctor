# 病历版本对照规则

同一项目再次诊断时，必须做版本对照，且旧病历保留不覆盖。

## 1. 定位旧病历

在项目约定的病历输出目录查找：
```
BP病历_[项目简称]_*_v*.md
```
匹配「项目简称」一致的所有病历，取版本号 `v` 最大的一份作为「上一版」。项目简称不同则视为新项目，不做对照。

## 2. 新病历命名与版本号

新病历文件名：`BP病历_[项目简称]_[YYYYMMDD]_v[序号].md`

- 若上一版存在，序号 = 上一版序号 + 1；
- 若不存在，序号 = 1。

旧病历文件**绝不覆盖、绝不删除**。同一天多次诊断也递增版本号，不复用文件名。

## 3. 新增「版本对照」章节

新病历在模板结构基础上，于「外部核验标记」之前插入：

```markdown
## 版本对照（v[旧] → v[新]）
| 维度 | 旧分 | 新分 | 变化 | 上一版核心问题是否解决 |
|---|---|---|---|---|
[逐维度填写：变化写 +N / −N / 0；是否解决写 是 / 部分 / 否 / 新增]

总分：旧 → 新（变化 ±N）
等级：旧 → 新
**仍未解决的高优先级问题：**
1. …
```

- 「上一版核心问题是否解决」须对照上一版病历「药方摘要」与「核心问题」逐条判断，不得含糊。
- 「仍未解决的高优先级问题」列出上一版优先级清单中，新版本仍未达标的项目。

## 4. 标尺版本（跨口径不可比）

病历头部含 `- 标尺版本：v[技能版本]`，由渲染器自动从本技能 `SKILL.md` 的 `version` 写入，无需手填。

评分口径（锚点、量程、等级区间）一旦调整，新旧病历就不在同一把尺子上：

- **同一标尺版本**：正常对照，分数变化可直接解释为改进或倒退；
- **跨标尺版本**：渲染器会自动在「版本对照」表前插入警示「两次诊断使用的评分口径不一致，分数与维度变化不可直接比较」。此时该章节只用于核对**「上一版的问题项是否已消除」**，不得引用分数涨跌作为结论，也不得在报告里宣称「分数提升了 N 分」；
- 若用户要求跨版本比较，先说明口径已变，再按问题项逐条对照。

已知历史口径：`v1.0.x` 及更早为「严标尺」（中位数约 40，55 分以上才「可以递出去」）；`v1.1.0` 起为「中位数 70」标尺。两段之间的分数**不可互相换算**。

## 5. 交付一致性

HTML 报告文件名仍为 `BP诊断报告_[项目简称]_[YYYYMMDD].html`（不带版本号，每版覆盖为最新诊断），但病历按版本累积，形成可追溯的修改对照链。报告与病历的核心分数、等级、问题清单必须一致。
